Setup for OSA's Databricks workspace administrators

During the workshop, each attendee creates their own Genie Agent from a set of P-card tables. Before the session, one person loads those tables into OSA's workspace by running a single notebook, and makes sure attendees can use them. That's the only setup. Attendees build everything else themselves.

What you need

  • A catalog where you can create a schema (CREATE SCHEMA, or ownership of the catalog).
  • Serverless compute, or a cluster, to run the notebook.
  • Permission to grant the attendees' group access to the schema and to a pro or serverless SQL warehouse.

Steps

What gets created

ObjectDetails
Schema<catalog>.osa_pcard_review with 6 tables: agencies, agency_budgets, cardholders, merchant_categories, transactions, monthly_statements. Every table and column has a description.

The notebook does not create any Genie Agents. Attendees create their own in section 2 of the workshop.

Safe to re-run. The data uses a fixed seed, so every run produces the same numbers. The notebook only overwrites tables it created itself, and stops if the schema already holds other tables with the same names.
Cleaning up afterward: attendees can delete their own agents. Then drop the schema with DROP SCHEMA <catalog>.osa_pcard_review CASCADE.
All data is synthetic. Agencies, cardholders, merchants and dollar amounts are all made up for training. Nothing here is an OSA finding.
