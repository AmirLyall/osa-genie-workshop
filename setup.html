Setup for the OSA data team

The business users follow along with a Genie Agent called OSA P-Card Review (Workshop). One person creates it once, in OSA's workspace, by running a single notebook. The notebook builds a synthetic P-card dataset, creates the agent with instructions and suggested questions, and can share both with the business users' group.

What you need

  • A catalog where you can create a schema (CREATE SCHEMA, or ownership of the catalog).
  • Permission to create Genie Agents and use a SQL warehouse (a serverless warehouse is best).
  • The name of the group the business users belong to, if you want the notebook to share everything for you.

Steps

What gets created

ObjectDetails
Schema<catalog>.osa_pcard_review with 6 tables: agencies, agency_budgets, cardholders, merchant_categories, transactions, monthly_statements. Every table and column has a description.
Genie AgentOSA P-Card Review (Workshop), in the folder of the person who runs the notebook, with business definitions, three example queries and five suggested questions.
Grants (optional)Read access on the schema and Can Run on the agent for share_with_group.
Safe to re-run. The data uses a fixed seed, so every run produces the same numbers. Tables are overwritten, and the agent is updated in place by title.
Cleaning up afterward: delete the agent from its folder, then drop the schema with DROP SCHEMA <catalog>.osa_pcard_review CASCADE.
All data is synthetic. Agency names are real, but every cardholder, purchase and dollar amount is made up for training. Nothing here is an OSA finding.
